# macOS desktop runtime and safe recovery

The Electron 39 shell wraps the **same** built React frontend, Express routes, domain package and SQLite repository used by the local browser runtime. Electron was chosen because the existing backend requires Node and `node:sqlite`; it does not duplicate writing logic or require a Node sidecar. The main process starts that backend exactly once on a free `127.0.0.1` port, waits for it before loading the window, focuses an existing window on a second app launch, and closes the server and database on quit. The renderer is sandboxed, context-isolated, without Node integration, with restricted navigation and narrowly scoped preload methods. The product does not need a remote host, Vite server or global Node installation to launch the packaged app. See `desktop/main.mjs`, `desktop/runtime.mjs`, and `desktop/preload.cjs`.

| Runtime             | Command                                      | Local writing database                                              |
| ------------------- | -------------------------------------------- | ------------------------------------------------------------------- |
| Browser development | `pnpm dev` or `pnpm build && pnpm start`     | `<repo>/data/workbench.sqlite` by default                           |
| Desktop development | `pnpm desktop:dev`                           | `<repo>/data/desktop-dev/workbench.sqlite`                          |
| Packaged desktop    | `pnpm desktop:build`, then launch the `.app` | `~/Library/Application Support/Language Workbench/workbench.sqlite` |

`pnpm desktop:build` produces `dist-desktop/mac-arm64/Language Workbench.app`. `pnpm desktop:smoke` first requires that build; it uses a disposable macOS temp profile, never the installed app's data. The current build is **unsigned and arm64-only**; copying it to Applications and launching from Finder/Dock may require macOS first-open approval. Signing, notarization, an auto-updater, a custom icon and Intel builds are not part of this pass. A first-run/unsigned replacement may prompt for Keychain permission; this is not yet a signed-update guarantee. Normal desktop downloads prompt for a save destination; the smoke uses a temporary automatic destination only within its validated disposable profile.

The packaged app-data directory also contains `logs/desktop.log`, optional legacy `.env`, `provider-credentials.json` and `backups/`. The credential file holds an Electron `safeStorage`-encrypted OpenAI key with owner-only permissions, **not** plaintext and **not** part of SQLite. Provider Settings → OpenAI Direct → Add API key is the normal BYOK path; a saved desktop key precedes process environment and legacy app-data `.env`. The renderer gets configured/source status, never a saved key. Remove key explicitly masks external/legacy credentials without deleting their files. Browser development continues to support its own repository-root `.env`. A real Test connection can use a tiny paid request; a model catalog Refresh is a separate explicit Models API call. `desktop:smoke` supplies synthetic credentials and intercepted responses, never a live paid call.

## What the backups contain

When `workbench.sqlite` already exists, **before** opening the repository/schema setup, desktop startup makes a timestamped SQLite online-backup snapshot in `backups/`. The snapshot includes committed document bodies, archived markers, global settings, library and provider-catalog metadata, including committed WAL transactions. It is a standalone SQLite snapshot; do not attach a source database's `-wal` or `-shm` files to it. There is no automatic pruning. On first empty launch there is no pre-existing database to back up. SQLite `CREATE TABLE IF NOT EXISTS` and supported version-one parsing defaults are **not** a general migration framework; a future schema change needs a deliberate upgrade test.

The startup `.sqlite` snapshot does **not** include `provider-credentials.json`, Keychain material, a legacy `.env`, logs, or unsaved browser/editor-memory changes. Conversely, copying the **entire** app-support directory manually _does_ copy its encrypted credential record and any plaintext legacy `.env`; treat that copy as private. Single-document/bulk JSON exports and finished-piece PDF/DOCX/Markdown are different, narrower formats, not substitutes for a full SQLite recovery copy. Wait for document and library **Saved** before relying on a backup. For routine cold full-folder copying, quit all app/server processes first and keep WAL/SHM alongside the original DB if present.

## Non-destructive staged restore

1. **Quit** Language Workbench and any backend using this database; do not point a development `DATA_DIR` at the live app-support folder. Confirm which snapshot you intend to use. Keep the existing app-support folder and all its backups untouched while you prepare recovery.
2. Copy the selected `backups/workbench-*.sqlite` to a **new, separately named empty staging folder** beside the normal app-support directory, naming the copied file `workbench.sqlite`. Do not copy old WAL/SHM files into staging. If you need a full-folder archival copy too, copy the existing app-support folder to another dated location before doing anything else.
3. If you can, verify a **disposable copy** of the staged DB using the local compiled server (after `pnpm build`). From the repository root, run `OPENAI_API_KEY= DATA_DIR="/path/to/disposable-verification-copy" PORT=4321 pnpm start` using a genuinely separate folder and a free port; inspect `http://127.0.0.1:4321`, then stop that server. Never set `DATA_DIR` to the live app-support directory. The automated proof in `tests/desktop.test.ts` does this restore with a representative older version-one document, confirms its content through the server, and confirms the changed source DB still exists.
4. With the app still closed, rename the current `Language Workbench` app-support folder to a dated `Language Workbench.before-restore-*` sibling. Rename the staged folder to **exactly** `Language Workbench`. This swaps names without deleting or overwriting the only current DB. Leave the preserved folder alone until restored documents/settings/library are checked.
5. Launch the installed app and confirm document data, library and routes. A SQLite-only restore does not restore the UI-managed encrypted credential file or legacy `.env`; re-add your own key in Provider Settings if needed. OpenAI routes remain exact but unavailable without a working credential—there is no silent paid fallback. If the restored profile is wrong, quit and reverse the folder-name swap; keep all originals and snapshots until satisfied.

Do not treat a successful startup as proof of complete recovery from an unsupported or future SQLite schema. Do not silently move the repo development DB into this directory. See [DEVELOPMENT.md](DEVELOPMENT.md) for test isolation, and [MAINTAINER-HANDOFF.md](MAINTAINER-HANDOFF.md) for invariants.
