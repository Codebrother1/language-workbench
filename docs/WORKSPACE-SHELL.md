# Workspace shell verification

The Workbench, Preview, and Inspector are docked views of the existing document, editor, and section workbench. They remain mounted when hidden. Layout settings persist `workbenchVisible`, `previewVisible`, `inspectorVisible`, density, primary view, and width weights; the last selected document ID is stored separately from content and editing focus in settings. Each document retains its last selected section ID without persisting incidental cursor text as a selection. Older settings receive defaults, and a missing or deleted document falls back to a surviving one. All seven nonempty pane combinations are available through the visible Show/Hide buttons. Manage documents in the document-actions menu separates Active and Archived; title search and ID-based selection support deliberate bulk archive, restore and export; filtered-out selections are counted explicitly, and permanent delete in this view applies only to archived documents. Duplicate titles gain a short opening cue (or edited time/short ID fallback). Manage and confirmation controls restore keyboard focus to their originating or surviving row. Archiving an active document selects a surviving draft or creates a blank one, and restoring one does not replace the current writing surface. Export selected/all produces one versioned document-only JSON backup with an archive-ID list; multi-document import is deferred, while single-document Import JSON remains available. The Layout menu offers Writing (Workbench dominant, Preview secondary), Review (Document View dominant with Inspector), Workbench only, All panes, and Reset layout. A visible divider supports pointer dragging and Left/Right arrow resizing. The last visible pane cannot be hidden accidentally.

Workbench shows persistent Draft and Parked count buttons above its cards. Each button scrolls the Workbench pane to its area without changing `Document.sections`. Parked prose remains editable, and Include keeps its exact-position chooser, now worded as At beginning / After a named section / At end while storing the same next-section ID boundary. A parked thought's removal dialog names it and retains session Undo; only an empty parked group can be deleted, after confirmation. Reload clears editor history rather than presenting an actionable stale Undo. The shell uses the same `EditorContent`; no copy of prose or separate editor is created. Reload and document switching reorient the selected Workbench card and Preview passage by section ID only when they are not already readable. Focus Preview restores pane scroll positions, then uses the same Workbench/Preview helpers if either selected section view would otherwise be clipped; a stacked page scrolls only for this explicit reading/restore action, not continuously during card editing. At ordinary desktop widths, the top and view bars take their natural heights in a viewport-height shell; the dock uses the remaining space and each pane scrolls independently, so the header does not scroll offscreen. On medium widths, a visible Inspector stacks beneath the other two panes; below 900 px, visible panes stack in one column and dividers disappear. Opening Saved takes there records the originating card and local scroll position; Return to section restores that place without a continuous pane lock. Card editing makes Preview a visibly labeled reading surface in persistent Preview chrome, naming the Workbench-owned section and offering an explicit way back to draft editing; leaving a parked card for a draft restores direct Preview editing, while draft-to-draft card editing stays in Workbench. Changing sections in editable Preview reveals the matching Workbench card and its local action row within the usable pane, accounting for sticky controls and a visible Lab dock, without coupling scrolling to typing. Document-ready orientation listens for bounded layout changes and stops ongoing smooth scroll when the writer interacts; non-prose focus restored by the browser does not falsely cancel it. A transient editor focus during hard reload is checked on the next animation frame before it counts as writer takeover, so a focus-and-blur during mount cannot strand the panes at the top; persistent prose focus still cancels. Pane toggles and presets remain usable there.

`tests/e2e/workspace-shell.spec.ts` covers pointer and keyboard resizing, width/visibility reload, presets, all pane combinations, unsent capture retention, Inspector direction retention, one editor instance, Draft/Parked navigation, parked editing and reinclusion, narrow stacking, and no page-level horizontal overflow. Existing card, boundary, Segue, clipboard, and parked-thought suites remain regression checks.

## Manual writing pass

Ran the built application on isolated port 4321 with temporary SQLite storage. Wrote **The marker on the map** as five rough thoughts, parked a side story, and revised its prose directly in the parked card. Writing gave the cards most width with Preview beside them and Inspector hidden. Review gave Document View the largest pane, with compact structure and Inspector alongside. Workbench only used the full width. Draft/Parked navigation made the side story reachable without scrolling through the four draft cards. Reincluding it preserved the revised prose. Reload restored the selected layout. Selecting Document View from a hidden Preview now reveals the document for that visit and restores the hidden Workbench preference on return.

A later large-document pointer check used an isolated offline fixture with nine draft sections, two parked thoughts and a named group. The writer manually dragged a draft card by its grip and confirmed the insertion marker, card reorder and live assembled-Preview reorder all worked. The existing drag implementation was left unchanged; automated pointer checks remain useful regression gates but are not substitutes for this human check.

## Remaining friction and next step

At narrower desktop widths, Inspector stacks below the other panes rather than sharing a row; this keeps the writing surface usable but means Inspector work can require vertical scrolling. Pane order is fixed. A constrained left/right order switch should follow only if repeated use shows that placement, rather than width or visibility, is the remaining obstacle. Arbitrary docking and floating windows are outside this model.
